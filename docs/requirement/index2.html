第2章

核心设计原则

五项北极星原则，v2.1 新增"自驱动闭环"。

直觉优先

上传=完成，查找=搜索，协作=进项目。消除认知负担。

智能赋能

Agent自动分类、推荐关联、预测权限。用户只觉得"系统很懂我"。

渐进披露

基础操作暴露最少信息，高级功能（权限矩阵、Agent编排）仅在需要时展开。

权限即边界

权限不等于限制，而是明确边界。越界操作有明确引导而非静默失败。

自驱动闭环 v2.1

项目是有生命周期的自驱动单元。定时任务驱动周期性检查，用户确认通知驱动关键节点推进。Agent完成工作后写文件告知下一环节，形成无人值守的推进链。

概念 NEW

项目 Skill 化

将项目本身作为 Skill 注册到 Agent 平台。Agent 被调度时读取 Skill 文件来"认识自己"。

项目 Skill 文件结构

每个项目创建后在 _project/ 下自动生成以下文件，是 Agent 自驱动的"操作系统"。

_project/自动生成
  collab-graph.md— 人类可读的协作关系说明书
  collab-graph.yaml— Agent可解析的结构化配置
  skill-{agent-name}.md— 每个Agent的角色说明书
    我是谁 · 我该怎么工作 · 输出后通知谁
  drive-config.yaml— 定时任务 + 通知触发器配置
  handoff-log.md— 交接日志

Agent 自指导三问

读取Skill文件后回答：我是谁（角色+职责）、我该怎么工作（输入/输出/规范）、做完之后怎么办（写交接文件+通知下一环节）。无需外部调度器。

交接文件协议

Agent完成任务后必须写「交付说明.md」，包含：产出物列表、关键决策、下一阶段注意事项。这是Agent间"说话"的载体。

概念 NEW

项目自驱动机制

两条驱动总线让项目持续运转：定时任务驱动周期性检查，用户确认通知驱动关键节点推进。

定时任务驱动

系统级调度器定期扫描项目状态，不需要用户在场。

  • 每30分钟检查新文件上传，触发分类Agent重新分析
  • 每小时检查上一阶段Agent是否完成，自动激活下一阶段
  • 每周生成进度摘要写入 _project/weekly-report.md
  • 监控文件变更频率，停滞时标记并通知

用户确认通知驱动

关键节点必须等待人类确认才能推进。

  • Agent完成需求分析后通知用户确认，确认后激活Design-Agent
  • Agent需访问无权限文件时通知审批，通过后自动补充上下文
  • 阶段性产出需用户"验收签字"才算阶段完成
  • 发现需求冲突时通知用户决策而非自行猜测
混合驱动：定时任务负责"巡逻"检查条件，用户确认负责"放行"关键节点。两者结合构成「自动推进+人工兜底」模型。
drive-config.yaml — 官网改版
scheduled_tasks:
  - name: "文件变更巡检"
    interval: "30m"
    action: "触发分类Agent重新分析"
  - name: "阶段推进检查"
    interval: "1h"
    action: "写完成报告 → 通知用户确认"

confirmation_gates:
  - name: "PRD确认"
    after: "PM-Agent 完成需求分析"
    on_confirm: "激活 Design-Agent"
    on_reject: "反馈写入 _project/feedback.md → PM-Agent修正"

第6章

非功能需求

性能

  • 分类推荐 P95 < 500ms
  • 全文搜索 P95 < 300ms
  • 列表刷新 < 200ms
  • 权限缓存命中 > 95%
  • 支持 10,000+ 文件流畅

兼容性

  • Chrome 90+ / Firefox 88+ / Safari 15+
  • 移动端 iOS Safari 15+ / Android Chrome 90+
  • 最小 375px 宽度响应式
  • 单文件 500MB，批量 2GB

安全性

  • 权限变更需用户确认
  • Agent权限申请需显式审批
  • 操作写入不可篡改审计日志
  • TLS 1.3 全程加密
  • 向量存储与文件存储隔离
  • GDPR合规（导出+注销）
第7章

工具选型

优先可本地部署方案，避免数据外泄。

SQLite-VSS

逻辑索引与向量存储。轻量嵌入式。

kNN嵌入式

nomic-embed-text-v1.5

文本嵌入，768维，中文支持，可本地部署。

768d本地

OpenClaw VFS

虚拟文件系统抽象层，统一多后端访问。

VFS多后端

CLIP ViT-B/32

多模态嵌入，图片语义理解，与文本共享向量空间。

multimodalCLIP
选型原则：所有嵌入模型支持量化后在 4GB VRAM GPU 运行。驱动引擎基于 APScheduler 或 Temporal 实现。
